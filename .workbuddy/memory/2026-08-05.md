## 补充：方案 A（Pyodide）能否部署 GitHub Pages —— 可以
- Pyodide 官方文档明确：任何正确设置 wasm MIME + CORS 的静态托管均可，GitHub Pages 在列。
- 关键点：跨域隔离头（COOP/COEP/CORP）只对 worker/SharedArrayBuffer 模式必需；ALT 转换是毫秒级纯 CPU 计算，主线程 loadPyodide 即可，GitHub Pages 无自定义响应头也不受影响（PyScript FAQ 同结论）。
- 包体积：只用 core 包（pyodide.asm.wasm ~6.3MB + python_stdlib.zip ~6MB + loader），原始约 13MB、压缩传输约 7MB；不要带 full（200MB+）。unicodedata/ast/dataclasses 等 ALT 所需 stdlib 均在 core 中。
- 部署注意：加 `.nojekyll` 防 Jekyll；.wasm MIME GitHub Pages 已支持 application/wasm（即便异常 Pyodide 也有非流式编译 fallback）；单文件远低于 100MB 限制。
- 代价：仓库 +~13MB、首屏加载 2–10s（国内访问 GitHub Pages 更慢）；GitHub Pages 无法自定义 Cache-Control，缓存策略不可控。终局仍是方案 B（零额外体积、秒开）。

## alt_converter.py 深度分析报告（docs/alt-converter-deep-analysis.md）
- 产出：docs/alt-converter-deep-analysis.md。核心结论：卡片朴素/复杂失败是确定性设计使然，非 bug。
- 关键机制：容量上限（2x2: 10节点/4Text/1Button/32文本单位；2x4: 18/8/2/72）；文本预算 maxVisibleTextUnits 是最硬失败点；字号自适应区间窄（primary 32→16 步进2，单行保护）；容器≤3子节点无弹性收缩；修复仅 4 次 prune 删低优先节点；3 个主题 × 8 组 token，模型只可选主题名。
- 失败模式 16 类（协议级 7 / 文本级 3 / 组件级 6），详见报告第 3 节。
- 优化建议三档：A 放宽容量与弹性（改 limits/fontAdaptation/加 layoutWeight）；B 扩展主题与组件能力；C 保留协议纯净走兼容路径（推荐）。
